## 1. 现状分析

### 1.1 当前系统架构概览

```
用户输入 → 意图分类器(T1-T5) → LLM推理 → System Prompt控制 → 输出
```

### 1.2 与网页版千问的差距矩阵

| 维度 | 当前系统 | 网页版千问 | 差距等级 | 影响 |
|------|---------|-----------|---------|------|
| **字数限制** | T5 ≤ 2000字 | 不设硬性上限（通常3000-8000字） | 🔴 严重 | 复杂题被强行截断 |
| **Temperature** | 0.0（完全确定性） | 0.7-0.9 | 🟡 中等 | 回答僵硬、缺乏变化 |
| **Max Tokens** | 4096 tokens | 8192-16384 tokens | 🟡 中等 | 长回答后半段被截 |
| **思维链引导** | 弱（仅要求标注依据） | 强制逐步推理思考 | 🔴 严重 | 跳步、省略过程 |
| **Few-shot示例** | 无 | 隐含大量优秀示例 | 🔴 严重 | 缺乏输出格式示范 |
| **教学风格** | 格式化模板（6段式） | 自然对话式教学 | 🟡 中等 | 缺乏亲和力 |
| **上下文记忆** | ✅ 128K系统 | ✅ 更长 | 🟢 相当 | — |
| **工具调用** | ✅ 多工具 | ✅ 更多 | 🟢 相当 | — |

### 1.3 根因分析

**根本原因：** 当前 System Prompt 过度依赖**结构化模板（6段式）** 和**僵化的字数限制**，本质上是在"约束"模型的输出格式，而不是"引导"模型输出高质量内容。这导致：

1. LLM的潜力被模板束缚——模型为了"套进模板"而缩减内容
2. 字数限制（2000字）直接截断了复杂问题的完整解答
3. Temperature=0 虽然保证了准确性，但牺牲了解释的丰富度
4. 缺乏思维链引导导致模型跳过中间推导步骤

## 2. 优化方案总览

本方案分为**三个渐进阶段**，每个阶段可独立交付：

```
Phase A（1-2h）→ Phase B（4-6h）→ Phase C（2-3天）
    ↓               ↓               ↓
  快速见效         深度优化         全面升级
  解决80%问题      接近千问         超越预期
```

**各阶段依赖关系：**
- Phase A 不依赖任何前置条件
- Phase B 依赖 Phase A
- Phase C 依赖 Phase A + Phase B，且需要更多测试验证

## 3. Phase A：快速见效（预估耗时：1-2小时）

> **核心目标：** 以最小改动解决80%的回答详细度问题
> **修改范围：** 2个文件（`system_prompt.py` + `dynamic_params.py`）
> **风险：** 极低（参数调整，不涉及架构变更）
> **效果预期：** 回答长度提升2-3倍，丰富度明显改善

**文件：** [prompts/dynamic_params.py](../prompts/dynamic_params.py)

## 4. Phase B：深度优化（预估耗时：4-6小时）

> **核心目标：** 通过 Prompt 工程技巧，引导模型输出更高质量的详细解答
> **修改范围：** 3个文件（`system_prompt.py` + `classifier_prompt.py` + `react_prompt.py`）
> **风险：** 中低（Prompt 改动，需要验证不同题型效果）
> **效果预期：** 回答质量接近千问水平的80%，教学感明显增强

### 4.1 重构 T5 模板：从"格式化表格"到"思维链引导"

**当前 T5 模板问题：**

当前模板是一份**严格的文档结构**（表格+编号列表），LLM会为了迎合格式而压缩内容。本质上是在让模型"填空"，而不是"讲课"。

**优化方案：** 将 T5 模板从"结构化表格"改为"思维链引导指令"。

```markdown
### 当前（格式化表格风格）

## 📋 一、题目确认
| 题目类型 | ... |
| 问题简述 | ... |
## ✅ 二、快速答案
> **正确答案**：[结果]

### 改为（思维链引导风格）

你在讲解一道数学题。请按以下思维链逐步展开：

**【第1步：理解题意】**
用自己的话重述题目，确保学生理解问题在问什么。
指出题目涉及的核心知识点和所属章节。

**【第2步：解题策略】**
- 说明你打算用什么方法/定理来解决
- 解释为什么选择这个方法（而不是其他方法）
- 如果有多种解法，简要提一下

**【第3步：详细推导】**
这一步最关键，请逐行写出：
- 每一步做了什么运算
- 每一步的依据是什么（定理/公式名称）
- 用 $...$ 或 $$...$$ 呈现公式

**【第4步：答案验证】**
- 验证结果的正确性（代入验证/量纲检查/边界检验）
- 指出常见的易错点

**【第5步：拓展总结】**
- 提炼本题的通用解题方法
- 给出1道类似练习题（含提示）
```

**关键变化：**
- ❌ 不再使用表格（表格限制回答长度）
- ❌ 不再用编号列表（编号列表诱导跳步）
- ✅ 用"思维链"代替"模板"，引导模型逐步思考
- ✅ 每步给出**具体标准**（如"逐行写出""验证结果"）

### 4.2 添加 Few-shot 示例（控制 Token 成本）

在 System Prompt 中嵌入一个**精简版优秀回答示例**，让LLM"有样学样"。

```markdown
### 优秀回答示例（参考）

用户提问：求函数 f(x)=x³-3x 在区间 [0,2] 上的最大值和最小值。

好的回答：
【第1步：理解题意】
这是一道闭区间最值问题，涉及导数应用。核心知识点是：
- 用导数求函数的单调区间
- 比较极值点和端点处的函数值
- 属于《高等数学》第三章"导数的应用"

【第2步：解题策略】
采用"求导→找驻点→比较函数值"的标准三步法。这是闭区间最值问题的通用解法。

【第3步：详细推导】
首先，对 f(x) 求导：
$$f'(x) = 3x^2 - 3$$

令 f'(x)=0，求解驻点：
$$3x^2 - 3 = 0 \implies x^2 = 1 \implies x = \pm 1$$
注意 x=-1 不在区间 [0,2] 内，所以只需考虑 x=1。

接下来计算各关键点的函数值：
- 端点: f(0) = 0³ - 3·0 = 0
- 驻点: f(1) = 1³ - 3·1 = -2
- 端点: f(2) = 2³ - 3·2 = 2

比较这几个值: -2 < 0 < 2

因此：
$$\max_{[0,2]} f(x) = f(2) = 2$$
$$\min_{[0,2]} f(x) = f(1) = -2$$

【第4步：答案验证】
验证：f'(x)=3x²-3 在 [0,2] 上的符号变化：
- x∈[0,1): f'(x)<0 → f递减
- x∈(1,2]: f'(x)>0 → f递增
符合最值规律 ✓

易错点：容易忘记检查端点 x=0 和 x=2 的函数值。

【第5步：拓展】
闭区间最值问题的通用方法：
1. 求 f'(x)
2. 解 f'(x)=0 找出驻点
3. 计算所有驻点和端点的函数值
4. 最大者为最大值，最小者为最小值

练习题：求 f(x)=x⁴-2x² 在 [-1,2] 上的最值（提示：4个关键点）
```

**注意：** 示例约400字（约600 tokens），是合理的成本。如果觉得token成本过高，可以精简到核心3步。

### 4.3 优化分类器的 T5 触发逻辑

**文件：** [prompts/dynamic_params.py](../prompts/dynamic_params.py)

**问题：** 当前规则中"解""求""计算"等词同时出现在多个规则中，导致被T5和T1同时匹配。

**修改内容：** 添加一条兜底规则——当用户问题包含明确的数学表达式（积分号、求导号、极限）时，**强制走T5**。

```python

    TaskType.FULL_SOLUTION,
    ["∫", "∑", "∏", "lim", "dx", "dy", "f'", "f''"],  # 数学符号触发
    [],  # 无低权重词
    [],  # 无否定词
```

### 4.4 降低 T5 场景的 planning 触发门槛

**问题分析：** 当前 `PlannerConfig.complexity_threshold = 0.6`，但根据之前的对话可以看到，复杂问题触发了 planning 模式后，**规划器本身会消耗大量 token 用于任务分解**，导致实际回答的 token 可用量减少。

**文件：** [agent_core/task_planner.py](../agent_core/task_planner.py)

**优化建议：**
- 将 `complexity_threshold` 从 0.6 提高到 **0.7**，减少不必要的planning触发
- 对于不需要 planning 的问题，直接走 ReAct 策略，回答更完整、更连贯

## 5. Phase C：全面升级（预估耗时：2-3天）

> **核心目标：** 实现自适应质量控制，让系统能根据问题复杂度自动调整回答的详细程度
> **修改范围：** 4个文件 + 可能需要添加动态参数调节模块
> **风险：** 中等（涉及自适应逻辑，需要充分测试）
> **效果预期：** 超过网页版千问的定制化程度

### 5.1 自适应 Token 分配器

**当前问题：** 所有 T5 问题使用相同的 max_tokens=4096，不分题目难易。

**实现思路：** 利用已有的 `LLMComplexityClassifier`（复杂度1-5分）的结果，动态分配 max_tokens。

```python
# 新增模块：自适应 Token 分配逻辑

# 复杂度 → 推荐 max_tokens 映射
COMPLEXITY_TOKEN_MAP = {
    1: 1024,    # 极简：1K tokens
    2: 2048,    # 简单：2K tokens
    3: 4096,    # 中等：4K tokens（当前默认值）
    4: 8192,    # 较难：8K tokens
    5: 12288,   # 困难：12K tokens
}
```

**涉及的改动点：**
- `agent_core/agent.py`：在 `stream()` 方法中，根据分类结果动态设置 max_tokens
- `prompts/dynamic_params.py`：可能需要支持运行时参数覆盖

### 5.2 追问引导机制

**目标：** 在回答末尾自动生成2-3个延伸问题，引导学生深入学习。

**实现方式：** 在 T5 System Prompt 末尾添加：

```markdown
### 追问引导（可选）

回答完成后，如果还有余力，可以在末尾添加1-2个追问建议：
- 💡 **想挑战类似的题吗？** [给出1道变式题]
- 🤔 **想深入理解背后的原理吗？** [引出一个进阶概念]
- 📚 **想知道这个知识点在考试中怎么考吗？** [给出备考建议]

注意：追问不是必须的，根据回答长度和问题复杂度灵活决定。
```

### 5.3 多风格路由

**目标：** 根据用户偏好和历史行为，自动匹配教学风格。

**实现方式：** 在 `PlanningContext` 中记录用户偏好，通过 System Prompt 动态注入风格指令。

```python
STYLE_TEMPLATES = {
    "详细": "请用最大篇幅详细讲解，不要省略任何中间步骤",
    "简洁": "直接给出核心推导，省略冗余解释",
    "直观": "多用类比和直观解释，少用数学符号",
    "严谨": "严格按照数学证明的格式，每步注明定理依据",
}
```

**前置条件：** 需要与用户画像系统集成（已有 `profile_analyzer.py`）。

## 6. 风险与注意事项

### 6.1 Token 成本增加预估

| 阶段 | 增加幅度 | 月预估增量（假设1万次对话） |
|------|---------|-------------------------|
| Phase A | +15~20% | ~$3-5 |
| Phase B | +30~50% | ~$8-12 |
| Phase C | +50~80% | ~$12-20 |

**注意：** T1/T2场景不受影响（占总对话的约40%），实际成本增加低于理论值。

### 6.2 潜在风险

| 风险 | 等级 | 应对措施 |
|------|------|---------|
| 回答过长导致超时 | 🟡 中 | Phase A仅调参不涉及超时逻辑；Phase B增加流式输出保障 |
| Few-shot示例导致风格固化 | 🟢 低 | 示例仅1个，不会主导模型行为 |
| 追问引导增加Token | 🟢 低 | 追问内容由模型自行决定长短 |
| 自适应逻辑引入Bug | 🟡 中 | Phase C需要单独测试验证，有回退机制 |
| 分类器误判（T5→T2） | 🟡 中 | 误判率约5%，可通过Phase B的数学符号规则降低 |

### 6.3 回退方案

每个阶段都保留了**一键回退**的能力：

- **Phase A**：恢复 `dynamic_params.py` 和 `system_prompt.py` 的原始参数（git checkout）
- **Phase B**：恢复 T5 模板为原始表格格式
- **Phase C**：通过配置开关 `enable_adaptive_tokens=False` 禁用自适应分配
