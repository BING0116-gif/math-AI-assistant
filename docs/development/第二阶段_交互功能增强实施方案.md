## 📋 一、第二阶段具体目标与预期成果

### 1.1 核心目标

#### 目标1：实现错题卡片展开/收起交互
- **描述**: 改造现有的错题列表展示方式，从"全部平铺显示"升级为"折叠式卡片"
- **预期效果**: 用户可以快速浏览错题概览，需要时再展开查看详情
- **用户体验价值**: 减少信息过载，提升浏览效率

#### 目标2：开发全功能详情模态框
- **描述**: 实现点击"查看详情"后弹出模态框，展示完整的错题信息
- **预期效果**: 提供沉浸式的错题查看体验，支持完整内容阅读
- **用户体验价值**: 专注查看单条错题，不受其他内容干扰

#### 目标3：集成MathJax数学公式渲染
- **描述**: 在详情界面正确渲染LaTeX格式的数学公式
- **预期效果**: 公式以美观的数学符号形式呈现，而非源码文本
- **用户体验价值**: 专业、可读的数学表达

#### 目标4：实现图片预览与放大功能
- **描述**: 为图片类型题目提供Lightbox效果的图片查看器
- **预期效果**: 点击图片可放大查看细节，支持缩放和拖拽
- **用户体验价值**: 清晰查看图片中的数学题目

#### 目标5：实现导航切换与快捷键支持
- **描述**: 在详情模态框中支持左右箭头切换上一题/下一题
- **预期效果**: 无需关闭模态框即可快速浏览相邻错题
- **用户体验价值**: 提升复习效率，流畅的操作体验

#### **任务 T2.1: 设计并实现错题卡片展开/收起功能**

**任务概述**: 将现有的平铺式错题列表改造为可折叠的卡片式布局

**负责人**: 前端开发工程师  
**工作量**: 1天（8小时）  
**前置条件**: 第一阶段数据存储修正已完成 ✅  
**依赖关系**: 无（独立任务）

##### 详细工作步骤：

**Step 1: 现状分析与需求梳理（0.5小时）**
```
输入:
  - 现有 error_book.html 的 renderErrorBook() 函数
  - 现有 CSS 样式定义
  
输出:
  - 当前渲染逻辑分析报告
  - 需要修改的代码清单
  
活动:
  1. 阅读 renderErrorBook() 函数完整代码
  2. 分析当前卡片的 HTML 结构
  3. 识别需要保留和修改的部分
  4. 记录现有的事件绑定机制
```

**Step 2: 设计新的卡片HTML结构（1小时）**
```
设计原则:
  - 保持向后兼容（不破坏现有数据字段）
  - 使用语义化 HTML5 标签
  - 考虑无障碍访问（ARIA属性）
  - 预留扩展空间（为后续详情按钮等）

目标结构:
<div class="error-card" data-error-id="{id}" data-expanded="false">
  <!-- 卡片头部（始终可见） -->
  <div class="card-header">
    <div class="header-left">
      <span class="expand-icon">▶</span>
      <h4 class="question-summary">{display_question}</h4>
    </div>
    <div class="header-right">
      <span class="mastery-badge">{掌握度星级}</span>
      <span class="status-tag">{已掌握/待复习}</span>
    </div>
  </div>
  
  <!-- 卡片主体（默认隐藏，点击展开） -->
  <div class="card-body" style="max-height: 0; overflow: hidden;">
    <div class="body-content">
      <!-- 错误原因 -->
      <section class="error-reason-section">...</section>
      
      <!-- 答案预览 -->
      <section class="answer-preview-section">...</section>
      
      <!-- 分类标签 -->
      <section class="categories-section">...</section>
      
      <!-- 操作按钮组 -->
      <div class="action-buttons">
        <button onclick="viewDetail('{id}')">📖 查看详情</button>
        <button onclick="toggleMastery('{id}')">✓ 掌握度</button>
        <button onclick="deleteError('{id}')">🗑️ 删除</button>
      </div>
    </div>
  </div>
</div>
```

**Step 3: 实现CSS动画效果（2小时）**

核心CSS规则：
- 卡片基础样式（圆角12px、阴影、过渡）
- 展开图标旋转动画（cubic-bezier缓动）
- 卡片主体高度动画（max-height过渡）
- Hover效果（阴影加深+轻微上移）

**Step 4: 实现JavaScript交互逻辑（2小时）**

核心函数：
- toggleErrorCard(errorId) - 切换单张卡片状态
- toggleAllCards(expand) - 批量操作所有卡片
- 自定义事件触发（cardToggle事件）

**Step 5: 重构renderErrorBook函数（2小时）**

修改策略：
- 保留原有数据获取和过滤逻辑
- 替换innerHTML生成为新的结构化模板
- 添加事件委托机制
- 确保向后兼容（使用第一阶段新增的字段）

**Step 6: 单元测试编写（0.5小时）**

测试场景（7个）：
- 默认状态验证
- 展开/收起交互
- 动画流畅度
- 批量操作
- 边界情况（空列表、大量记录）

**交付物清单**:
- [ ] 更新后的 renderErrorBook() 函数
- [ ] 新增CSS样式代码块
- [ ] toggleErrorCard() 和 toggleAllCards() 函数
- [ ] 单元测试文件 test_card_toggle.js
- [ ] 技术说明文档

**验收标准**:
- ✅ 页面加载时所有卡片处于收起状态
- ✅ 点击卡片任意位置可切换展开/收起
- ✅ 展开动画时长300ms，使用cubic-bezier缓动曲线
- ✅ 展开后显示：错误原因、答案预览（前500字符）、分类标签、操作按钮
- ✅ 收起后只显示：题目摘要、掌握度、状态标签
- ✅ 支持50+条错题同时渲染不出现明显卡顿
- ✅ 单元测试通过率100%

### 5.2 应对策略摘要

#### R01 MathJax CDN问题（高风险）
- **预防**: 多CDN源、timeout设置、考虑本地打包
- **缓解**: 优雅降级（LaTeX语法高亮）、loading提示、重试按钮
- **应急**: 本地部署、临时禁用渲染、通知用户
- **责任人**: 前端开发
- **监控**: 每次打开时检测，>5秒触发

#### R02 动画性能（中风险）
- **预防**: 仅GPU加速属性、will-change、200-400ms时长
- **缓解**: 设备性能检测、简化低端设备动画、虚拟滚动
- **检测**: requestAnimationFrame单帧>50ms则标记reduced-motion

#### R03 浏览器兼容性（中风险）
- **预防**: Autoprefixer、caniuse查询、browserslist配置、Polyfill
- **缓解**: 兼容性测试矩阵、@supports降级样式、UA收集修复

#### R04 需求变更（中风险）
- **预防**: 启动会充分讨论、可交互原型、变更控制流程
- **缓解**: 影响评估、敏捷迭代、Must-have/Nice-to-have分级
- **流程**: 提出→PM评估→技术分析→讨论→决策→更新计划

#### R05 进度延迟（中风险）
- **预防**: 任务细化≤0.5天、20%缓冲时间、每日跟踪、松耦合
- **应急**: 
  - 延1天：加班+调整T2.6时间
  - 延2-3天：砍T2.4高级功能
  - 延3天+：紧急会议重新评估范围

#### R06 第一阶段Bug影响（中风险）
- **预防**: 运行第一阶段测试套件、检查实际数据、确认API结构、防御性编程
- **缓解**: 前端二次验证、TypeScript/JSDoc、清晰错误提示、即时沟通通道
- **代码示例**: safeGet(obj, path, defaultValue) 安全访问嵌套字段

### 5.3 风险监控机制

示例用例（每个函数至少3-5个）:

### 6.4 性能保障措施

#### 性能预算（Performance Budget）
```
关键指标限制:
  - First Contentful Paint (FCP): ≤1.5s
  - Time to Interactive (TTI): ≤3.0s
  - Layout Shift (CLS): ≤0.1
  - Modal Open Time: ≤200ms
  - Card Expand Animation FPS: ≥55
  - Memory Growth: ≤50MB（持续使用1小时后）
```

#### 性能优化技术
```
1. 资源优化:
   - CSS/JS压缩和混淆
   - 图片懒加载（Intersection Observer）
   - 字体子集化（仅包含使用的字符）
   
2. 渲染优化:
   - 虚拟滚动（Virtual Scroll，>50条时启用）
   - will-change提示（谨慎使用）
   - requestAnimationFrame替代setTimeout
   
3. 网络优化:
   - HTTP/2推送关键资源
   - Cache-Control合理设置
   - Service Worker离线缓存（可选）
   
4. 监控指标:
   - Real User Monitoring (RUM)
   - Performance Observer API
   - 自定义埋点（关键操作耗时）
```

#### 性能测试方法
```javascript
// 自动化性能测试示例
async function measureModalOpenTime() {
  const start = performance.now();
  await openDetailModal('test-id');
  const duration = performance.now() - start;
  
  console.log(`Modal open time: ${duration.toFixed(2)}ms`);
  
  // 断言
  if (duration > 200) {
    throw new Error(`Performance regression: ${duration}ms > 200ms`);
  }
}
```
