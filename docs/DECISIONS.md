# 决策日志：多用户安全隔离与生产数据一致性修复

## D-001：生产数据库

状态：已确认

生产和 Compose 默认使用 PostgreSQL。SQLite 只允许显式本地开发配置；生产不得自动回退 SQLite。

## D-002：会话隔离与存储介质

状态：已确认

本次将所有会话访问统一为 `(user_id, session_id)`，但不迁移 Redis。原因是跨用户泄漏由键设计和身份传递造成，存储迁移会扩大回归面，且不是修复隔离漏洞的必要条件。

## D-003：Thought 所有权

状态：已确认

Thought 按复合身份存储/读取。非所有者和不存在的会话统一返回 404，避免 session ID 枚举。管理员默认无跨用户 Thought 读取权限。

## D-004：Mock 与 Dashboard

状态：已确认

- Mock Router 仅 `DEBUG=true` 注册。
- Dashboard 在所有环境均要求 admin。
- 当前 `User.role` 为字符串，已能表达 admin；本次不增加角色系统或管理员 CLI。

## D-005：事件幂等

状态：已确认

使用数据库唯一约束竞争处理权，禁止 check-then-act 和内存字典。必须记录处理状态。

失败事件标记为 `failed`；下一次收到相同 event ID 时允许一个调用者原子地重新取得处理权。不启动后台自动重试，也不在本次增加最大次数。业务成功但最终状态更新失败的深度补偿另行设计。

## D-006：记忆/画像外键

状态：已确认

- `users.id`、`memories.user_id`、`user_profiles.user_id` 统一为 `String(36)`。
- 外键使用 `ON DELETE RESTRICT`。
- 不把孤儿数据归入默认用户。
- 发现孤儿时停止迁移，导出审计结果并由人工决定隔离、修复或删除。

## D-007：测试策略

先重建最小可用测试环境并记录基线；每个垂直切片同步补测试。8 条关键测试不得含占位、宽松状态码或跳过。Docker 冷启动作为独立 CI Gate。

## D-008：刷新 Token 轮换

状态：已确认

刷新使用数据库条件更新 `is_revoked=false -> true` 原子取得轮换权；同一 JTI 的并发刷新只有一个成功。轮换前还必须确认用户仍存在且处于激活状态。
