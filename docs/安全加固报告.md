## 二、CORS策略优化

### 2.1 实施内容

**配置参数**:
- `CORS_ORIGINS`: 限制为可信来源
- `CORS_MAX_AGE`: 预检请求缓存时间
- `ALLOW_METHODS`: 允许的HTTP方法
- `ALLOW_HEADERS`: 允许的请求头

**配置值**:
```python
CORS_ORIGINS = [
    "http://localhost:8000",
    "http://127.0.0.1:8000",
    "http://localhost:3000",
    "http://127.0.0.1:3000",
]
CORS_MAX_AGE = 600  # 10分钟
ALLOW_METHODS = ["GET", "POST", "PUT", "DELETE", "OPTIONS"]
ALLOW_HEADERS = ["Authorization", "Content-Type", "Accept"]
```

### 2.2 安全HTTP头

新增安全响应头：

| 响应头 | 值 | 作用 |
|--------|-----|------|
| X-Content-Type-Options | nosniff | 防止MIME类型嗅探 |
| X-Frame-Options | DENY | 防止点击劫持 |
| X-XSS-Protection | 1; mode=block | 启用XSS保护 |
| Referrer-Policy | strict-origin-when-cross-origin | 控制referrer信息 |
| Content-Security-Policy | default-src 'self'; ... | 内容安全策略 |
| Permissions-Policy | camera=(), microphone=(), geolocation=() | 权限策略 |

### 2.3 实施效果

- ✅ 跨域请求来源限制在可信域名
- ✅ 预检请求缓存减少重复OPTIONS请求
- ✅ 安全头保护防止常见Web攻击

## 三、JWT认证机制

### 3.1 功能实现

**核心功能**:

| 功能 | 说明 | 实现状态 |
|------|------|---------|
| 令牌生成 | 支持access token和refresh token | ✅ |
| 令牌验证 | 签名验证、过期检查、黑名单检查 | ✅ |
| 令牌刷新 | 使用refresh token获取新access token | ✅ |
| 过期处理 | 自动清除过期令牌 | ✅ |
| 令牌撤销 | 支持主动登出 | ✅ |

### 3.2 技术实现

**令牌结构**:
```
Header.Payload.Signature

Payload包含:
- user_id: 用户标识
- exp: 过期时间戳
- iat: 签发时间戳
- type: 令牌类型(access/refresh)
- jti: 令牌唯一标识
```

**配置参数**:
- `JWT_SECRET_KEY`: 签名密钥（生产环境必须使用强随机字符串）
- `JWT_ALGORITHM`: HS256
- `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`: 1440分钟（24小时）
- `JWT_REFRESH_TOKEN_EXPIRE_DAYS`: 30天

### 3.3 API端点

| 端点 | 方法 | 功能 | 是否需要认证 |
|------|------|------|-------------|
| `/api/auth/register` | POST | 用户注册 | 否 |
| `/api/auth/login` | POST | 用户登录 | 否 |
| `/api/auth/refresh` | POST | 刷新令牌 | 否 |
| `/api/auth/logout` | POST | 用户登出 | 是 |

### 3.4 认证流程

```
登录流程:
用户 → POST /api/auth/login → 验证用户名密码 → 返回token pair → 存储到localStorage

请求流程:
用户请求 → 检查Authorization头 → 验证token → 允许访问/拒绝

刷新流程:
token过期 → 自动使用refresh token → 获取新token → 继续请求
```

## 四、输入过滤与验证

### 4.1 XSS攻击防护

**检测模式**:
- `<script>`、`<iframe>`、`<object>`、`<embed>`、`<form>`标签
- `javascript:`、`vbscript:`协议
- `on*`事件处理器（如onclick、onload）
- SVG和MathML标签
- `expression()`和`url()` CSS函数

**处理方式**:
- 检测到攻击特征时返回400错误
- 错误信息包含威胁类型标识

### 4.2 SQL注入防护

**检测模式**:
- `UNION SELECT`组合
- `INSERT INTO`、`DELETE FROM`、`DROP TABLE`等关键字
- SQL注释符（`--`）
- `OR 1=1`等条件注入
- `EXEC`、`EXECUTE`执行命令

### 4.3 路径遍历防护

**检测模式**:
- `../` 和 `..\` 路径遍历
- `/etc/passwd`、`/etc/shadow`敏感文件
- `\windows\system32`敏感目录

### 4.4 输入验证规则

| 验证项 | 规则 |
|--------|------|
| 最大长度 | 默认50000字符 |
| 空字符 | 自动过滤\0字符 |
| 数据类型 | 严格类型检查 |
| 嵌套结构 | 递归验证数组和对象 |

## 六、潜在风险评估

### 6.1 风险清单

| 风险 | 概率 | 影响 | 等级 | 应对措施 |
|------|------|------|------|---------|
| JWT密钥泄露 | 低 | 高 | 🔴 | 使用环境变量，定期轮换 |
| 暴力破解登录 | 中 | 中 | 🟠 | 增加登录失败次数限制 |
| 令牌劫持 | 低 | 高 | 🔴 | 使用HTTPS，设置HttpOnly cookie |
| 输入过滤绕过 | 低 | 中 | 🟡 | 定期更新正则规则 |
| CSRF攻击 | 低 | 中 | 🟡 | 使用CSRF令牌 |

### 6.2 当前未实现的安全功能

| 功能 | 优先级 | 建议时间 |
|------|--------|---------|
| 登录失败次数限制 | P1 | 第2周 |
| HTTPS强制跳转 | P1 | 部署前 |
| CSRF防护 | P2 | 第3周 |
| 密码复杂度要求 | P2 | 第2周 |
| 用户会话管理 | P2 | 第3周 |

### 6.3 安全建议

1. **生产环境配置**:
   - 使用强随机JWT密钥（32字节以上）
   - 启用HTTPS
   - 配置反向代理（Nginx）
   - 关闭DEBUG模式

2. **密钥管理**:
   - 不要将密钥提交到代码仓库
   - 使用密钥管理服务（如Vault）
   - 定期轮换密钥

3. **日志审计**:
   - 记录所有认证失败尝试
   - 监控异常访问模式
   - 定期安全审计
