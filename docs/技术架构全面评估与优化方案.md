## 一、方案背景

### 1.1 项目概述

**数学AI助手**（"贸大数助"）是对外经济贸易大学学生开发的高等数学学习智能辅助系统。该系统基于大语言模型（LLM）技术，旨在帮助学生解决高等数学学习中的痛点，包括积分、微分等难点问题的解答。

**当前系统能力：**
- ✅ 智能数学问题解答（支持多种题型）
- ✅ 多模态图像识别（Qwen-VL视觉模型）
- ✅ 流式对话交互（SSE实时响应）
- ✅ 错题本管理功能
- ✅ 多轮对话上下文保持

**核心技术栈：**
- **后端**: Python + FastAPI + LangChain + Qwen-Max LLM
- **前端**: 原生HTML5 + CSS3 + JavaScript + MathJax
- **数据存储**: JSON文件（错题本）+ 内存（会话历史）
- **部署方式**: 单体应用，Uvicorn ASGI服务器

### 1.2 方案编写背景

随着用户规模的扩大和功能的持续迭代，当前系统在以下方面面临挑战：

#### 业务驱动因素：
1. **用户体验要求提升** - 用户期望获得类似ChatGPT/Doubao的流畅交互体验
2. **性能压力增大** - 并发访问量增长导致响应延迟增加
3. **功能扩展需求** - 需要支持更复杂的数学场景和个性化学习路径
4. **安全合规要求** - 教育数据保护法规对系统安全性提出更高标准

#### 技术演进需求：
1. **架构现代化** - 从单体架构向微服务架构演进，提升系统弹性
2. **工程化水平** - 提升代码质量、测试覆盖率、文档完整性
3. **可观测性** - 建立完善的监控、日志、告警体系
4. **生态开放** - 构建插件平台，支持第三方能力接入

### 1.3 方案范围界定

**本方案覆盖范围：**
- ✅ 后端架构重构与优化
- ✅ 前端技术栈升级
- ✅ 系统性能调优
- ✅ 安全体系加固
- ✅ 工程化规范建立
- ✅ 微服务化改造规划
- ✅ 多Agent协作架构设计

**本方案不涉及范围：**
- ❌ 具体的数学算法改进（属于业务逻辑优化）
- ❌ 新功能特性开发（如语音识别、AR展示等）
- ❌ 商业模式设计与运营策略
- ❌ 硬件设备选型与采购

## 四、技术架构优化详细方案

### 4.1 后端框架评估与优化

#### 4.1.1 LangChain框架深度评估

##### 当前使用方式分析

**现有实现模式**（基于agent_core/agent.py代码审查）：

```python
# 当前架构：完整的LangChain链式调用
组件链路:
  ChatPromptTemplate 
    → MessagesPlaceholder (注入历史)
      → ChatOpenAI (Qwen-Max)
        → StrOutputParser
          → RunnableWithMessageHistory (会话管理)
```

**LangChain在本项目中的实际作用评估：**

| 能力 | 是否使用 | 使用深度 | 替代难度 | 保留建议 |
|------|---------|---------|---------|---------|
| LLM调用抽象 | ✅ 已使用 | 浅（仅封装OpenAI接口） | 低 | ⚠️ 可考虑移除 |
| 多轮对话管理 | ✅ 已使用 | 中（RunnableWithMessageHistory） | 中 | ✅ 保留但需优化 |
| 流式输出支持 | ✅ 已使用 | 深（astream方法） | 高 | ✅ 强烈保留 |
| Agent工具调用 | ❌ 未使用 | - | - | ❌ 当前无需 |
| Chain组合 | ❌ 未使用（单链结构） | - | - | ❌ 当前无需 |
| Memory持久化 | ❌ 未使用（仅内存存储） | - | - | 🔶 需新增 |
| Output Parser | ✅ 已使用 | 浅（StrOutputParser） | 低 | ⚠️ 可自定义 |

##### 性能瓶颈分析

**基准测试假设数据**（基于行业经验估算）：

| 瓶颈类型 | 具体表现 | 性能损耗 | 对用户感知的影响 |
|---------|---------|---------|---------------|
| **抽象开销** | LangChain Runnable层的序列化/反序列化 | +15-20% 延迟 | 可感知（流式输出卡顿） |
| **消息构建** | 每次请求重新构造Pydantic消息对象 | +5-10ms/次 | 几乎无感 |
| **内存占用** | 会话历史全量存储在InMemoryChatMessageHistory | 线性增长 | 长会话时明显 |
| **扩展性限制** | LangChain插件机制对自定义工具不够灵活 | - | 限制工具生态发展 |

**结论**：对于当前相对简单的使用场景（单LLM调用+流式输出+会话历史），LangChain提供了约**20%的性能开销**，但换来了代码的可读性和标准化。建议采用**渐进式解耦策略**而非完全移除。

#### 4.1.2 后端架构优化三阶段路线

##### 阶段一：轻量化重构（第1-4周）

**目标**：在不改变技术栈的前提下，优化当前实现的性能和可维护性

**具体措施A：精简LangChain使用层级**

**优化前（当前实现）**：
```python
# agent_core/agent.py 第70-95行
class SimpleAgent:
    def _initialize_langchain(self):
        self.llm = ChatOpenAI(
            model="qwen-max",
            temperature=0,
            api_key=self.api_key,
            base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
            streaming=True
        )
        
        prompt = ChatPromptTemplate.from_messages([
            ("system", SYSTEM_PROMPT),
            MessagesPlaceholder(variable_name="history"),
            ("human", "{input}"),
        ])
        
        output_parser = StrOutputParser()
        base_chain = prompt | self.llm | output_parser
        self.chain = RunnableWithMessageHistory(
            base_chain,
            self._get_session_history,
            input_messages_key="input",
            history_messages_key="history",
        )
```

**优化后（推荐实现）**：
```python
# 新建 app/core/llm_service.py

class OptimizedLLMService:
    """
    轻量级LLM服务 - 直接使用OpenAI SDK，减少抽象层
    
    优势：
    - 延迟降低15-20%（消除LangChain中间层）
    - 代码更直观，调试更容易
    - 完全控制请求/响应流程
    """
    
    def __init__(self, config: LLMConfig):
        self.client = AsyncOpenAI(
            api_key=config.api_key,
            base_url=config.base_url,
        )
        self.model = config.model
        self.temperature = config.temperature
        
        # 会话存储（后续迁移至Redis）
        self.session_store = SessionStore()
    
    async def stream_chat(
        self, 
        message: str, 
        session_id: str,
        system_prompt: str = None
    ) -> AsyncIterator[str]:
        """流式对话 - 逐token返回"""
        
        # 获取会话历史
        history = await self.session_store.get_history(session_id)
        
        # 构建消息列表
        messages = [{"role": "system", "content": system_prompt or DEFAULT_SYSTEM_PROMPT}]
        messages.extend(history)  # 历史消息
        messages.append({"role": "user", "content": message})
        
        # 调用流式API
        stream = await self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            stream=True,
            temperature=self.temperature
        )
        
        full_response = ""
        async for chunk in stream:
            content = chunk.choices[0].delta.content
            if content:
                full_response += content
                yield content
        
        # 保存至会话历史（异步，不阻塞响应）
        asyncio.create_task(
            self.session_store.add_message(session_id, "user", message)
        )
        asyncio.create_task(
            self.session_store.add_message(session_id, "assistant", full_response)
        )
```

# app/core/agent/orchestrator.py (概念设计)
from enum import Enum
from typing import List, Dict, Any
import asyncio

class TaskPriority(Enum):
    CRITICAL = 1    # 用户实时等待的任务
    HIGH = 2        # 重要后台任务
    NORMAL = 3      # 常规后台任务
    LOW = 4         # 非紧急预处理

class AgentOrchestrator:
    """
    Agent编排器 - 任务调度中心
    
    核心能力：
    1. 任务分解（复杂问题→子任务树）
    2. 智能调度（根据Agent专长分配任务）
    3. 并行执行（多个Agent同时工作）
    4. 结果聚合（合并多个Agent输出为统一答案）
    5. 质量控制（交叉验证答案准确性）
    """
    
    def __init__(self):
        # 注册专业Agent
        self.agents = {
            'math_solver': MathSpecialistAgent(),      # 数学解题专家
            'concept_explainer': ConceptTeacherAgent(), # 概念讲解专家
            'error_analyst': ErrorAnalystAgent(),       # 错因分析专家
            'vision_parser': VisionParserAgent(),       # 图像解析专家
            'quality_checker': QualityCheckAgent()      # 质量审核员
        }
        
        # 任务队列（按优先级排序）
        self.task_queue = PriorityQueue()
        
        # 结果合并器
        self.result_merger = ResultMerger()
    
    async def process_complex_task(self, user_query: str) -> Dict[str, Any]:
        """处理复杂任务的完整流程"""
        
        # Step 1: 任务分解
        subtasks = await self.decompose_task(user_query)
        
        # Step 2: Agent选择与调度
        scheduled_tasks = []
        for subtask in subtasks:
            best_agent = self.select_best_agent(subtask.type)
            scheduled_tasks.append((best_agent, subtask))
        
        # Step 3: 并行执行
        tasks = [
            agent.execute(subtask) 
            for agent, subtask in scheduled_tasks
        ]
        results = await asyncio.gather(*tasks, return_exceptions=True)
        
        # Step 4: 结果聚合
        successful_results = [r for r in results if not isinstance(r, Exception)]
        final_response = self.result_merger.merge(successful_results)
        
        # Step 5: 质量检查
        quality_report = await self.agents['quality_checker'].validate(final_response)
        
        return {
            'response': final_response,
            'quality_score': quality_report.score,
            'confidence_level': quality_report.confidence,
            'agents_used': [agent.name for agent, _ in scheduled_tasks],
            'processing_time_ms': quality_report.latency,
            'suggestions': quality_report.improvement_suggestions
        }

    chunkSize: 5,           // 每批渲染5个字符（平衡性能与体验）
    renderThreshold: 50,    // 每50ms最多渲染一次（节流）
    pauseOnPunctuation: true, // 遇到句号/问号停顿一下
  });

  useEffect(() => {
    if (containerRef.current) {
      containerRef.current.scrollTop = containerRef.current.scrollHeight;
    }
  }, [displayedText]);

  useEffect(() => {
    if (isComplete && onComplete) {
      onComplete();
    }
  }, [isComplete, onComplete]);

  return (
    <MathJaxProvider>
      <div 
        ref={containerRef}
        className="prose prose-sm max-w-none streaming-content"
        dangerouslySetInnerHTML={{ __html: formatMarkdownIncremental(displayedText) }}
      />
      
      {!isComplete && (
        <span className="inline-block w-2 h-4 bg-blue-500 animate-pulse ml-1" />
      )}
    </MathJaxProvider>
  );
};
