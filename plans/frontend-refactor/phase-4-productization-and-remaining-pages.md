# Phase 4：其余页面与产品化

> 前置条件：Phase 3 核心学习闭环通过验收  
> 建议周期：8～12 个工作日  
> 阶段定位：统一剩余体验、达到小规模真实试用标准

## 1. 阶段目标

把 Phase 3 验证过的设计模式扩展到课程目录、知识地图、错题复盘、历史对话、认证与设置等页面，并补齐移动端、性能、可访问性、可观测性和小规模试用所需能力。

阶段完成后，产品应能交给 10～30 名大学生连续使用两周，而不是只能由开发者演示。

## 2. 用户故事

- 作为学生，我可以从课程目录或知识地图理解自己学过什么、薄弱在哪里、下一步是什么。
- 作为错题较多的学生，我可以按错因和复习时间处理错题，而不是在长列表中翻找。
- 作为移动端用户，我可以完成提问、学习、作答和复盘，不需要桌面端补操作。
- 作为使用辅助技术的学生，我可以通过键盘和屏幕阅读器完成主要路径。
- 作为运维者，我可以看到错误率、延迟、AI 成本和关键漏斗。
- 作为产品负责人，我可以根据真实试用数据决定下一门课程和下一批功能。

## 3. 范围

### 本阶段必须完成

- 课程目录体验统一；
- 2D 个性化知识地图或可靠的课程树降级方案；
- 错题复盘工作台；
- 对话历史与学习上下文管理；
- 认证、个人设置、数据导出与删除入口；
- 全面响应式、键盘与可访问性；
- 性能优化和懒加载；
- 前端错误监控、结构化日志和关键产品指标；
- 10～30 人、两周的小规模试用计划；
- 文档、发布、回滚和支持流程。

### 本阶段不做

- 不扩展教师/班级系统；
- 不做知识图谱正式管理后台；
- 不做 3D 视图作为主操作界面；
- 不在试用数据前扩展所有大学数学课程；
- 不建立复杂商业化和订阅系统；
- 不进行与用户价值无关的大规模后端重构。

## 4. 纵向切片

### Slice 4.1：课程目录与知识地图

#### 要做什么

课程目录负责稳定浏览章节层级；知识地图负责展示前置关系、掌握状态和推荐路径，两者不能混为一个视图。

首选 2D 地图能力：

- 节点：mastered、learning、weak、available、locked、unseen；
- 关系：prerequisite 为主，related/easily_confused 为辅助；
- 点击节点打开检查器；
- 高亮一跳邻居和当前推荐路径；
- 移动端只显示聚焦节点与一跳关系；
- 3D 星系仅作为可选总览并延迟加载。

#### 验收标准

- 树和图使用清晰不同的数据契约；
- 锁定节点解释缺少哪些前置；
- 状态不只依赖颜色；
- 地图空、部分数据缺失、超长名称时可用；
- 图接口不存在时自动降级为课程树，不阻塞学习；
- 100～300 节点交互流畅；
- 图谱模块不进入非图谱页面首屏包。

### Slice 4.2：错题复盘工作台

#### 要做什么

把错题从 CRUD 列表升级为复盘任务：

- 默认按错因和到期复习分组；
- 支持知识点、题型、错因、掌握状态和日期筛选；
- 每道错题展示来源、最近错误、下次复习和掌握变化；
- 提供复测、同错因变式、回知识点三个主动作；
- 删除提供可恢复撤销或明确二次确认。

#### 验收标准

- 无错题时给出如何开始的动作；
- 筛选状态可通过 URL 或返回导航恢复；
- 复测结果回写 LearningRecord、UserSkill 和 ErrorItem；
- 已掌握不等于永久隐藏，仍可查看历史；
- 批量操作有确认、进度和失败报告；
- 移动端不依赖右键或 hover。

### Slice 4.3：对话历史、认证与个人控制

#### 要做什么

- 对话历史从全局主导航降级为提问模块的二级信息；
- 支持搜索、重命名、删除、恢复当前对话；
- 明确本地草稿与服务端会话的状态；
- 完善登录过期、刷新令牌失败和账号锁定反馈；
- 设置页提供主题、学习偏好、数据导出和账号数据删除入口。

#### 验收标准

- 会话归属由服务端验证；
- 登录失效不会静默丢失未发送输入；
- 删除操作明确对象、后果和恢复可能性；
- 用户能够导出自己的学习数据并请求删除；
- 普通用户看不到管理入口；
- 退出登录后敏感状态从前端清理。

### Slice 4.4：移动端、可访问性与性能

#### 要做什么

对全产品执行系统性质量检查，而不是逐页补丁。

检查范围：

- 375/768/1024/1440px；
- 手机横屏；
- 200% 文本缩放；
- 键盘和屏幕阅读器；
- reduced motion；
- 慢网、断网、请求超时；
- 长对话、长公式、50+ 错题；
- 路由懒加载和重型图模块拆包。

#### 验收标准

- 无键盘陷阱；
- 焦点可见且顺序符合视觉顺序；
- 所有输入有 label，错误靠近字段并可被读出；
- 正文对比度达到 WCAG AA；
- 核心触控目标至少 44px；
- 无非预期横向滚动；
- 主要内容不会被固定导航/输入区遮挡；
- 核心页面定义性能预算，并记录生产构建结果；
- 慢网时有 skeleton/进度，超时有重试。

### Slice 4.5：可观测性、试用与发布

#### 要做什么

为真实试用建立最小运营闭环。

记录：

- 页面和 API 错误；
- SSE 中断率；
- 主要页面 P50/P95；
- 模型、token、耗时和成本；
- 今日任务 → 学习 → 作答 → 复测漏斗；
- 严重数学错误反馈；
- 用户主动“不懂/错误”反馈。

#### 验收标准

- 日志不记录密码、token、完整敏感内容；
- requestId、userId、sessionId、knowledgePointId 可关联但遵守隐私策略；
- 错误看板可以区分前端、后端、模型和内容问题；
- 发布有备份、迁移、健康检查和回滚步骤；
- 试用用户有反馈入口和隐私说明；
- 两周后形成量化结果、访谈摘要和功能决策清单。

## 5. 小规模试用方案

### 人群

- 10～30 名正在学习高等数学的大学生；
- 覆盖基础薄弱、中等和较强学生；
- 至少连续使用两周。

### 核心任务

1. 完成一次文字或图片提问；
2. 完成一个极限知识点学习任务；
3. 做至少两道练习并查看反馈；
4. 处理一次错题复测；
5. 查看自己的知识状态和下一步。

### 重点问题

- 用户是否知道首页该做什么？
- AI 的解释是否帮助理解，而非只是给答案？
- 学生是否理解掌握度变化？
- 推荐是否相关且难度合适？
- 哪一步最容易退出？
- 哪些视觉元素造成干扰或不可信感？

## 6. 测试与发布策略

- 全量后端 pytest；
- 前端单元/组件测试；
- Playwright 覆盖注册、学习、作答、错题、复测、退出登录；
- PostgreSQL 空库迁移和备份恢复演练；
- 生产构建的 bundle 分析；
- 可访问性自动扫描 + 人工键盘检查；
- 关键页面视觉回归；
- 灰度或小流量发布，保留快速关闭新 UI 的回退能力。

## 7. 推荐切片/PR 顺序

1. 课程目录与 2D 地图；
2. 错题复盘工作台；
3. 对话历史、认证和设置；
4. 全站移动端与可访问性；
5. 性能、监控和发布；
6. 小规模试用与反馈修正。

## 8. 风险控制

- 图谱后端未稳定时优先交付可靠课程树，不阻塞阶段；
- 不用复杂动画掩盖加载慢；
- 试用阶段冻结大功能，只修复 P0/P1 问题和关键体验；
- 产品指标必须用于决策，不能只收集不分析；
- 用户反馈涉及数学错误时进入高优先级人工复核；
- 数据导出和删除应复用既有安全接口，不在前端伪实现。

## 9. Definition of Done / 最终退出条件

- [ ] 四个核心一级入口视觉和交互统一；
- [ ] 课程目录、知识地图、错题复盘和对话历史可用；
- [ ] 核心任务在手机和桌面均可完成；
- [ ] 关键页面达到 WCAG AA 基础要求；
- [ ] 前端构建、组件测试、核心 E2E、后端测试和空库迁移通过；
- [ ] 错误、延迟、成本和学习漏斗可观测；
- [ ] 数据导出与删除入口可用；
- [ ] 10～30 名学生完成两周试用；
- [ ] 输出继续、调整、删除三类产品决策；
- [ ] 是否扩展线性代数或概率论由试用结果决定，而不是预先假定。
