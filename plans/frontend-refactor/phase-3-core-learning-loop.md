# Phase 3：核心学习闭环

> 前置条件：Phase 2 全部退出条件通过  
> 建议周期：10～15 个工作日  
> 首版内容范围：高等数学——函数、极限与连续  
> 下一阶段：[Phase 4：其余页面与产品化](./phase-4-productization-and-remaining-pages.md)

## 1. 阶段目标

交付第一条真正完整、可度量的学生学习路径：

> 注册/登录 → 今日任务 → 打开知识点 → 学习内容 → 完成练习 → 获得分层反馈 → 更新掌握度 → 记录错题 → 获得下一步推荐

这是四个阶段中业务价值最高的阶段。设计、后端、内容和测试必须围绕同一条纵向路径推进。

## 2. 用户故事

- 作为新学生，我可以从一个推荐知识点开始，而不必先理解所有功能。
- 作为基础薄弱学生，我可以按概念、例题、提示和练习逐步学习。
- 作为答错的学生，我先看到错误位置和提示，而不是立即看到完整答案。
- 作为完成练习的学生，我可以看到掌握状态为何变化。
- 作为复习者，我可以把错误关联到知识点和错因，并获得后续复测。
- 作为返回用户，我可以从首页继续上次未完成的任务。

## 3. 范围

### 首版内容范围

- 只覆盖函数、极限与连续；
- 20～30 个经过审核的知识点；
- 至少 100 道人工确认并关联稳定知识点 ID 的题目；
- 每个核心知识点至少包含概念、关键公式/定义、例题、基础练习和退出测验；
- 练习按基础、标准、综合三级组织。

### 本阶段必须完成

- 今日首页真实学习状态；
- 任务化知识点学习页；
- 作答与反馈接口/流程；
- 掌握度更新和解释；
- 聊天与知识点上下文联动；
- 错题记录和下一步推荐；
- 学习事件埋点和转化漏斗；
- 核心 E2E 和内容质量检查。

### 本阶段不做

- 不扩展线性代数和概率论；
- 不做完整考试系统；
- 不做教师班级管理；
- 不做复杂 BKT/IRT；
- 不做 AI 自动发布课程内容；
- 不做完整管理员图谱编辑器；
- 不让 LLM 单独判定客观题正确性或掌握度。

## 4. 核心数据与接口决策

### 4.1 复用现有模型

- Course / Chapter / KnowledgePoint / KnowledgePointResource；
- Question；
- LearningRecord；
- UserSkill；
- ErrorItem；
- ChatSession / ChatMessage。

不另建一套“学习页专用题目”或“前端掌握度”数据。

### 4.2 建议稳定契约

现有读取接口继续使用：

```text
GET /api/knowledge/courses
GET /api/knowledge/courses/{course_id}/tree
GET /api/knowledge/points/{point_id}
GET /api/knowledge/points/{point_id}/learning
POST /api/chat
POST /api/chat/multimodal
GET/POST/PUT/DELETE /api/error-book...
```

若现有接口不能表达完整闭环，应增加面向行为的学习接口，而不是由前端同时调用多个内部接口拼装事务：

```text
GET  /api/learning/today
POST /api/learning/attempts
GET  /api/learning/attempts/{attempt_id}/feedback
GET  /api/learning/points/{point_id}/progress
POST /api/learning/points/{point_id}/complete
```

具体名称可在实现前评审，但必须满足：服务端从认证上下文获取用户、一次提交具有幂等键、作答记录与掌握度更新保持一致。

### 4.3 LearningContext

页面和对话共享最小上下文：

```text
courseId
knowledgePointId
questionId（可选）
learningRecordId / attemptId（可选）
sessionId（进入对话时）
entrySource（today / course / chat / review）
```

它只保存标识和来源，不在前端复制课程正文、标准答案或掌握度权威值。

## 5. 纵向切片

### Slice 3.1：今日任务到知识点学习

#### 要做什么

首页从静态功能卡改为真实的今日工作台，优先显示一个主要下一步：继续上次知识点、处理到期复习，或开始基础知识点。

页面至少包括：

- 主提问框；
- 今日主要任务；
- 继续学习；
- 待复习摘要；
- 最近掌握变化。

#### 验收标准

- 新用户获得一个可学习的基础节点；
- 返回用户优先继续未完成任务或到期复习；
- 首页只有一个主 CTA；
- 无学习数据时不显示伪造进度；
- API 失败时提供重试和进入课程目录的降级路径；
- 点击任务携带正确 LearningContext 进入学习页。

### Slice 3.2：任务化知识点学习空间

#### 要做什么

将知识点学习页组织为可完成任务流：

1. 学习目标与前置要求；
2. 可选先验检测；
3. 核心概念与直觉；
4. 定义/公式/推导；
5. Worked example；
6. 渐隐提示练习；
7. Exit ticket；
8. 结果和下一步。

#### 验收标准

- 用户始终知道当前步骤与完成进度；
- 可返回上一步且不丢失已保存草稿；
- 数学公式、长推导和图片在移动端可读；
- 内容缺失时明确显示，不使用空白卡片；
- 每个阶段具有稳定资源类型和排序；
- 未满足前置知识时说明缺少内容，但允许按产品策略预览；
- 退出测验未完成前不自动标记已掌握。

### Slice 3.3：练习提交、判题与反馈

#### 要做什么

支持学生提交最终答案和必要步骤。判题策略按题型分层：

- 客观表达式：规范化 + SymPy/规则等价；
- 数值题：精度、单位、定义域校验；
- 选择/判断：确定规则；
- 复杂推导/证明：关键步骤规则 + 评分量表 + LLM 辅助，明确不确定性。

反馈顺序：

1. 是否正确；
2. 错误发生在哪一类步骤；
3. 一个针对性提示；
4. 允许再次作答；
5. 用户主动请求后展示完整解答。

#### 验收标准

- 重复点击不会创建多条作答；
- 未清洗输入不进入危险表达式解析；
- 错误反馈包含恢复动作；
- 提示次数、作答时间和正确性记录到 LearningRecord；
- 标准答案不在首次提交前下发到浏览器；
- 判题无法确认时显示“需要复核”，不伪造确定结果；
- 网络失败后可安全重试，不重复更新掌握度。

### Slice 3.4：掌握度、错题与下一步

#### 要做什么

提交完成后，以可解释规则更新 UserSkill，并让学生看到状态变化原因。

首版因素：

- 是否正确；
- 题目难度；
- 尝试次数；
- 提示次数；
- 最近学习时间；
- 是否为间隔后的复测。

答错时可确认或修正错因，再加入错题本；完成时推荐一个主要下一步和最多两道练习。

#### 验收标准

- 单次简单题正确不会直接标记完全掌握；
- 每次掌握度变化有原因和时间；
- 错题关联稳定知识点和 questionId；
- 推荐不越过未满足的前置节点；
- 推荐解释“为什么”；
- 推荐失败不影响作答结果；
- 用户 A/B 掌握状态完全隔离。

### Slice 3.5：对话与学习上下文联动

#### 要做什么

将聊天页拆为对话主区与可收起上下文检查器。用户从知识点或题目进入聊天时，检查器展示本轮课程、知识点、学习目标、相关资料和后续动作。

关键动作：

- 换一种讲法；
- 只给提示；
- 解释某一步；
- 生成变式；
- 加入错题；
- 回到知识点；
- 定位到知识地图（如果可用）。

#### 验收标准

- `ChatView` 不再承担错题 Dialog、SSE 解析、上下文展示和全部输入逻辑；
- SSE 中断可恢复或明确重试；
- 切换对话不会串用知识点上下文；
- 关键动作是结构化事件，不依赖拼接自然语言猜测；
- 移动端上下文使用 bottom sheet；
- 不展示模型内部思维链，只展示可验证的工具状态和来源。

## 6. 内容生产与审核

- 课程负责人先确定知识点、学习目标和前置关系；
- AI 可生成草稿，但只能进入 draft/pending；
- 人工审核数学正确性、符号、难度、来源和版权；
- 每道正式题具有标准答案、关键步骤、允许等价表达和知识点关联；
- 建立不少于 100 道的首版金标评测集；
- 内容发布保留版本和审核记录。

## 7. 测试与质量指标

### 自动化测试

- 单元：判题规则、掌握度、推荐排序、前置关系；
- API：今日任务、幂等作答、反馈、用户隔离；
- 组件：学习步骤、作答状态、错误恢复、上下文面板；
- E2E：完整新用户学习闭环；
- LLM 评测：知识点识别、数学正确性、提示质量和严重错误。

### 业务指标

- 首页任务点击率；
- 知识点学习完成率；
- 首次练习提交率；
- 提示后再次作答率；
- 回答到推荐练习转化率；
- 复测通过率；
- 严重数学错误率；
- 页面/API P50、P95 延迟和单次 AI 成本。

## 8. 推荐切片/PR 顺序

1. LearningContext 与今日数据契约；
2. 今日首页到知识点入口；
3. 任务化学习页；
4. 作答/判题闭环；
5. 掌握度、错题和推荐；
6. 对话上下文与组件拆分；
7. 全链 E2E、指标和内容验收。

## 9. 风险控制

- 后端接口未完成时允许使用明确的开发 fixture，但不得作为生产逻辑；
- 掌握度规则必须版本化，便于后续替换；
- LLM 辅助判题必须保留原始输入、模型版本和评分理由；
- 不在客户端保存标准答案和权威掌握度；
- 核心路径失败时优先保证作答记录不丢失；
- 课程内容不足时缩小知识点数量，不使用未经审核内容填充数量。

## 10. Definition of Done / 退出条件

- [ ] 新用户可从今日页完成一次完整学习闭环；
- [ ] 返回用户可以继续未完成学习或到期复习；
- [ ] 至少 20 个知识点和 100 道题通过人工审核；
- [ ] 作答、反馈、掌握度、错题和推荐数据一致；
- [ ] 客观题不依赖 LLM 单独判定；
- [ ] 核心路径在 375px 与 1440px 可用；
- [ ] 自动化 E2E 可重复通过；
- [ ] 学习漏斗和严重错误指标可查询；
- [ ] 真实演示不依赖手工修改数据库或浏览器存储。
