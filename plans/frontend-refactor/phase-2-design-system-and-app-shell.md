# Phase 2：设计系统与应用外壳

> 前置条件：Phase 1 全部退出条件通过  
> 建议周期：5～8 个工作日  
> 下一阶段：[Phase 3：核心学习闭环](./phase-3-core-learning-loop.md)

## 1. 阶段目标

建立统一、可复用、可访问的前端设计系统和响应式 AppShell，让现有首页、聊天、课程目录、学习页和错题本在不改变业务行为的情况下运行于新外壳中。

这一阶段结束后，产品应已经“看起来属于同一个系统”，但不要求核心学习闭环全部完成。

## 2. 用户故事

- 作为学生，我在任意核心页面都能知道自己在哪里并快速前往主要功能。
- 作为手机用户，我可以使用不超过 4 个主要入口完成导航，内容不会被固定栏遮挡。
- 作为键盘用户，我可以跳过导航、看到焦点并操作所有主要控件。
- 作为开发者，我可以使用统一令牌和基础组件开发新页面，而不用复制页面 CSS。
- 作为维护者，我只需修改一处主题定义即可改变全站语义色。

## 3. 范围

### 本阶段必须完成

- 语义化设计令牌；
- 浅色工作台与深色认知画布基础主题；
- AppShell、桌面侧栏、顶栏、移动端导航；
- 统一按钮、图标按钮、输入、弹窗/抽屉、状态标签、Toast、空/错/加载状态；
- 路由激活态、标题、返回行为和主内容焦点；
- 旧页面接入新外壳；
- 移除结构性 emoji、原生 prompt/confirm 和重复主题入口；
- 前端组件测试基础设施；
- 视觉与可访问性检查。

### 本阶段不做

- 不新增学习记录或作答后端接口；
- 不重写 Chat Agent 或 SSE 协议；
- 不完成个性化今日任务算法；
- 不实现正式知识图谱编辑器；
- 不重做所有页面内部内容；
- 不迁移到 React、Tailwind 或另一套 UI 库。

## 4. 架构决策

### 4.1 组件分层

```text
AppShell
├─ PrimaryNavigation
├─ AppTopBar
├─ MainContent
├─ ContextPanel（可选）
└─ MobileNavigation / MobileSheet

UI primitives
├─ AppButton / IconButton
├─ AppInput / FormField
├─ AppDialog / AppDrawer
├─ StatusBadge / MasteryBadge
├─ AppToast
└─ LoadingState / EmptyState / ErrorState / Skeleton
```

Element Plus 可继续作为行为底座，但业务页面只通过受控封装或统一主题使用，避免每页覆盖一套样式。

### 4.2 主题与令牌

- 合并 SCSS 变量和 CSS 自定义属性的重复语义；
- CSS 自定义属性作为运行时主题权威源；
- SCSS 只保留编译期布局常量或映射；
- 令牌分为 canvas、surface、text、border、action、status、knowledge、review、graph；
- 禁止用品牌主色同时表达成功、选中、知识点和警告；
- 深色图谱主题是局部表面，不强制全站暗色。

### 4.3 响应式结构

- ≥1280px：248px 左侧导航 + 主区域 + 可选 360～400px 上下文面板；
- 768～1279px：72px 图标轨或可收起侧栏，上下文为抽屉；
- <768px：底部最多 4 项一级导航，详情使用 bottom sheet；
- 使用 `min-height: 100dvh` 思路，固定栏预留内容间距；
- 不允许通过缩小桌面布局解决移动端。

## 5. 纵向切片

### Slice 2.1：令牌与基础组件

#### 要做什么

建立最小设计系统并用一个内部展示页或 Story Gallery 验证组件所有状态。

必须覆盖：

- Primary / Secondary / Tertiary / Danger / Icon 按钮；
- 文本、密码、搜索、多行输入；
- focus、hover、pressed、loading、disabled、error；
- Dialog、Drawer、Toast；
- Skeleton、EmptyState、ErrorState；
- 掌握、学习中、薄弱、锁定、推荐等状态。

#### 验收标准

- 页面没有新增硬编码品牌色；
- 正文对比度至少 4.5:1；
- 点击区至少 44×44px；
- 颜色状态同时有文字或图标；
- 动效尊重 reduced motion；
- 组件在浅色和深色表面均可读；
- 组件测试覆盖关键状态与键盘操作。

### Slice 2.2：AppShell 与导航

#### 要做什么

替换旧 `LayoutDefault/Sidebar/TopBar` 的外观与责任，使所有核心页面使用统一外壳。

桌面导航顺序：

1. 今日；
2. 提问；
3. 课程；
4. 错题复盘。

对话历史进入“提问”的二级区域，不再占据全局侧栏主体。新提问仍作为显著主动作。

#### 验收标准

- 当前路由有清晰激活态；
- 深层页面仍可访问一级导航；
- 返回时保留合理的滚动与筛选状态；
- 桌面侧栏可折叠，移动端不会覆盖内容；
- 路由切换后焦点进入主内容；
- 存在 skip-to-content；
- 不再重复显示两个主题切换器；
- 未实现入口要么不出现，要么明确说明不可用，不能静默失效。

### Slice 2.3：旧页面适配新外壳

#### 要做什么

把现有 Home、Chat、KnowledgeCatalog、KnowledgeLearning、ErrorBook 挂载到 AppShell，保持业务操作不变，解决明显布局冲突。

#### 验收标准

- 所有现有路由仍可直接访问和刷新；
- SSE 对话、公式渲染、课程树、学习内容和错题 CRUD 不因外壳变化失效；
- 页面只存在一个主滚动容器；
- 固定输入区不遮挡最后一条消息；
- 弹窗打开/关闭时焦点正确返回；
- 原生 `prompt/confirm` 替换为统一 Dialog；
- emoji 结构图标替换为统一 SVG 图标。

### Slice 2.4：视觉一致性与响应式验收

#### 要做什么

对四个核心页面执行桌面和移动端适配，处理加载、空状态、失败和超长内容。

#### 验收标准

- 375、768、1024、1440px 无非预期横向滚动；
- 长公式可滚动或换行，不撑破布局；
- 长标题、空课程、无错题、网络超时均有稳定布局；
- 交互不依赖 hover；
- 键盘可遍历所有主要动作且无焦点陷阱；
- 页面首屏没有无意义自动旋转或持续动画；
- 构建产物按路由拆分，重型图谱模块不进入首屏主包。

## 6. 测试策略

- Vitest：令牌辅助逻辑、组件状态、composable；
- Vue Test Utils：按钮、Dialog、导航、错误和加载状态；
- axe 或等价检查：关键页面无严重可访问性错误；
- Playwright 冒烟：每个核心路由可访问、导航正确、Dialog 可操作；
- 视觉检查：375/768/1440px，浅色/深色画布，reduced motion；
- 回归：Phase 1 的五条行为全部保持。

## 7. 推荐切片/PR 顺序

1. 语义令牌与基础组件；
2. AppShell 与导航；
3. 旧页面接入；
4. 响应式与可访问性修正；
5. 删除已确认无引用的旧样式，仅在回归测试通过后执行。

## 8. 风险控制

- 新旧主题短期共存时，用明确作用域隔离，禁止互相覆盖；
- 不在本阶段拆分所有业务逻辑，避免外观和行为同时大改；
- Element Plus 定制集中在主题入口，避免大量 `!important`；
- 字体加载失败时必须有可靠中文系统字体回退；
- 大组件拆分只提取稳定边界，不为追求行数制造碎片组件。

## 9. Definition of Done / 退出条件

- [ ] 所有核心路由使用新 AppShell；
- [ ] 全站只有一套权威语义主题；
- [ ] 基础组件覆盖完整交互状态；
- [ ] 原生 prompt/confirm 和结构性 emoji 已移除；
- [ ] 375～1440px 核心页面可用；
- [ ] Phase 1 冒烟路径无回归；
- [ ] 组件测试、前端构建和核心 E2E 通过；
- [ ] Phase 3 可以直接复用设计系统实现学习闭环，无需再次改壳。
